星环科技实训营四周复盘：把量化投研做成一条工程流水线

项目：星环科技（Transwarp）· AI-Native 组合投资实训营（TransAlpha），校企合作实习项目，2026/7/27–8/23 共四周。我在 5 人投资决策委员会（IC）中任量化研究员，持风控否决权。三个核心产出均已开源：AlphaForge、quantbacktest、three-flywheels。

先交代结构：这不是”写个策略”的实习

四周里做的事情分三层：

  1. 因子研究与组合构建——因子打分、组合构建、回测校验、风险检查、归因复盘，走完整的投研闭环；
  2. 工具链建设——把每一环沉淀成可复现、可测试的代码；
  3. 投委会机制——每个决策要过 IC，风控口持有否决权。

这套结构决定了四周的产出不是一份报告，而是一条流水线。

产出一：AlphaForge——多因子选股，评分体系先行

  • 100 分制三层评分，而不是单一的加权打分——不同性质的因子放进不同的层，避免”一个好因子被三个平庸因子的噪声淹没”；
  • 21 个行业的自适应阈值：同一分数在不同行业的含义不同，阈值跟着行业分布走；
  • 214 个测试用例兜底。评分体系的 bug 是最难肉眼发现的——一个排序反转就可能让整个组合倾斜，测试是唯一可靠的防线。

产出二：quantbacktest——回测引擎的细节决定可信度

89 个测试用例的事件驱动回测引擎，重点都花在”让回测变得不那么乐观”上：

  • T+1 交易约束（当天买入不能当天卖出）；
  • 涨跌停限制（涨跌停价位的委托不成交）；
  • 印花税与滑点（成本侧真实化）；
  • 凯利仓位管理（仓位由胜率与赔率推导，而不是拍脑袋）。

回测高估收益的方式有无数种，引擎的工作就是把最常见的几种堵死。

产出三：three-flywheels——数据质量的旁路验证

零侵入旁路模块，8 个文件、10 个 CLI 命令、7 条业务红线、62 个单元测试、接入 CI。实测成绩：

  • 检出某数据源 market_cap 字段 100% 缺失；
  • 139 条异常记录聚类为 9 类，让”修数据”从大海捞针变成按类扑灭。

设计原则是零侵入：验证逻辑跑在业务流程旁边，不进主链路——出问题时不拖累业务，没问题时持续站岗。

产出四：Buffett-Value-Agent

参与 Agent 方向的探索：用 Agent 把价值投资的分析框架工程化。这次经历也直接影响了之后的方向选择——比起传统量化，Agent 工程的可复用性更吸引我，这也是我后来把求职方向定为 AI 应用 / Agent 工程的起点之一。

复盘：四周里最值钱的三条经验

  1. 先建测试，再谈迭代。 214 / 89 / 62 个测试不是负担，是四周内敢反复改代码的底气。
  2. 数据质量用旁路持续验证，不要靠事故驱动。 market_cap 100% 缺失这种问题，主动扫一次就能发现，被动发现时损失已经发生。
  3. 投委会机制的价值在”否决权”。 流程上多一道风控否决，执行时就会少很多”先跑起来再说”的侥幸。

以上数字均来自三个开源仓库的 README 与测试统计，可在 GitHub 逐一复核。
